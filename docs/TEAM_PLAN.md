## Что строим

MediPlan — веб-продукт для семей в США, которые в ноябре выбирают медстраховку от работодателя.

1. Пользователь загружает SBC-файлы планов одного или двух работодателей.
2. Проверяет извлечённые цифры и вводит взнос с зарплаты (в SBC его нет).
3. Заполняет профиль семьи.
4. Получает лучший вариант покрытия с ценой для хорошего, обычного и плохого года.

Оплата: годовая подписка около $49. Интерфейс на английском, питч на русском. Название: MediPlan.

## Что уточнили организаторы

Из официального FAQ по кейсу. Это меняет приоритеты.

- **Пейвол обязателен.** Минимум — работающий пейвол с понятной ценой, одной страницы с ценами мало. Stripe в тестовом режиме с тестовой картой на экране даёт плюс по главному критерию.
- **Механика возврата должна быть встроена и работать**, описания в деке недостаточно. У нас это трекер года `/year`.
- **Удержание — это продление подписки**, а не ежедневные заходы. Для сезонного продукта годовая подписка нормальна, если понятно, почему человек вернётся в следующем сезоне. Плюс за ценность вне сезона.
- **B2C-версия продукта, который продают только работодателям, считается новым углом.** Вопросы про ALEX, Nayya и open enrollment в FAQ задала другая команда, значит, у нас есть прямой конкурент на хакатоне. Отличаемся расчётом для двух работодателей и проверкой плохого года.
- **«Не обёртка над ChatGPT»:** расчёты делает наш код, модель только читает документ. Организаторы прямо назвали такую схему настоящим ядром.
- **Жюри вводит свои данные и читает код.** Пример через тот же пайплайн приветствуется, но должен быть подписан как пример. Ручной ввод обязан работать: своих SBC у жюри нет.
- **Здоровье:** без медицинских рекомендаций и без лишних данных о здоровье. Спрашиваем количество визитов и рецептов, а не диагнозы.
- **Дек:** на английском, PDF, не больше 10 слайдов вместе с титульным и приложениями, продукт показываем скриншотами. Нужны цифры: цена, стоимость привлечения по каналам, удержание, LTV, с источниками (RevenueCat, Adapty).
- **Плюсы:** реальные интервью или опросы американцев, мобильная вёрстка, README с инструкцией запуска и списком зависимостей.
- **Мёртвых кнопок быть не должно:** что не работает, прячем.

### Чьи файлы

Чтобы не было конфликтов при слиянии, каждый правит только своё.

- **Абука:** `src/app/api/**`, `src/app/start/**`, `src/components/start/**`, `src/components/paywall/**`, `src/lib/extract/**`, `src/lib/domain/reference-prices.ts`
- **Борч:** `public/samples/**`, `docs/research/**`, `src/app/pricing/**`
- **Общее, менять только с предупреждением в чате:** `src/lib/domain/plan.ts`, `src/lib/domain/profile.ts`, `src/lib/store/session.ts`

### Контракты между линиями

- Абука отдаёт `ExtractedPlan` из `src/lib/domain/plan.ts`. Ответ API: `{ plan, warnings }`.
- Экран `/start` собирает из него `Plan` (добавляет работодателя A или B и взносы) и сохраняет через `saveSession`.
- Экран `/profile` собирает `Household` из `src/lib/domain/profile.ts` и сохраняет туда же.
- Экран `/result` читает `loadSession()` и вызывает `recommend(household, plans, prices)` из `src/lib/calc`.

Экран проверки цифр на `/start` одновременно служит ручным вводом плана. Если извлечение не сработало, пользователь вводит цифры сам, и продукт всё равно работает.

## Форс-мажоры

### У пользователя, в продукте

- Каждый вариант считается для плохого года: скорая, приёмное отделение, госпитализация. Событие назначается тому члену семьи, для которого оно дороже всего.
- Если удар плохого года больше накоплений семьи, вариант не рекомендуется, даже если он самый дешёвый в обычный год.
- Если вся семья на плане одного работодателя, вердикт предупреждает о риске потери этой работы.
- Для каждого варианта показан потолок: взносы плюс годовой максимум расходов.

### У команды

| Что случилось | Что делаем |
| --- | --- |
| Кто-то выпал | Его линию берёт подменяющий из таблицы ролей |
| Извлечение работает плохо | Ручной ввод на экране проверки цифр |
| Кончились кредиты или сломался ключ OpenAI | Ручной ввод, кнопка примера на заранее извлечённых и проверенных реальных SBC |
| Не успеваем | Режем по порядку: Stripe, уточняющие вопросы, сверка счетов в трекере. Сквозной поток, пейвол и трекер не режем |
| Сломался ноутбук или интернет | Пушим в GitHub не реже раза в час, раздача интернета с телефона |
| Vercel не деплоит | Тот же репозиторий на Netlify |

## Правила работы с репозиторием

- Ветка `main` всегда собирается: перед пушем `npm test`, `npm run typecheck`, `npm run lint`.
- Каждый работает в своей ветке и сливает в `main` маленькими порциями, не реже раза в час.
- Ключи только в `.env.local` и в настройках Vercel. В репозиторий и чаты их не кладём.
- Жюри читает репозиторий: без закомментированного кода, без данных-заглушек в продакшене.

## Объективная оценка по критериям

| Критерий | Оценка | Главный риск |
| --- | --- | --- |
| Работает, 40% | Движок готов и покрыт тестами | Точность извлечения на разных SBC; взносы приходится вводить руками |
| Ценность и удержание, 20% | Экономия считается в долларах. Жюри важнее продление подписки, чем ежедневные заходы | Сезонность: ценность вне сезона даёт только трекер года, его надо успеть |
| Проблема и пользователь, 15% | Подтверждена цифрами KFF | Команда сама не из этой аудитории, на вопросах жюри нужен уверенный владелец темы |
| Бизнес, 15% | 154 млн человек со страховкой от работодателя | Для $100M ARR нужно около 2 млн платящих семей; привлечение сезонное |
| Оригинальность, 10% | B2C-версию того, что продают работодателям, организаторы назвали новым углом | Ту же идею, судя по FAQ, делает ещё одна команда |

Открытые долги:

- Справочные цены в `reference-prices.ts` пока оценочные. До сдачи каждой нужен источник.
- Сеть врачей и список лекарств не проверяются автоматически. В интерфейсе это надо сказать прямо.
- Нужен дисклеймер: продукт не является страховым брокером.
